04 — How I work

Understand it, then make it boring.

01

Read the system first

Before changing a line I trace the request path, the schema, and where it actually hurts. Most bugs are drift, not logic.

02

Measure, then change

Timings and query counts before the refactor, the same numbers after. If it isn't measurably better, it doesn't ship.

03

Leave tests behind

Coverage on the modules that carry money and data, so the next person can move fast without breaking the ledger.
